## 一、现状：GenDic segments 模式（当前实现）

`GalTransl/Backend/GenDic.py` 流程：

```
输入文件 → 分段（≤512字符/段）
        → vaporetto 分词，提取候选词（仅：未登录词+片假名 / 正则片假名序列 / 人名）
        → 词频过滤（≥2 次，或人名，或纯片假名）
        → solve_sentence_selection 加权集合覆盖，选 ≤128 个「完整片段」
        → 把片段发给 AI（GENDIC_PROMPT：「从输入的日文片段中构建术语表」）
        → AI 在文本里找专有名词并翻译（TSV 输出）
        → 跨片段投票聚合 dic_votes → 去重 → 存「项目GPT字典-生成.txt」
```

**现状问题**：
1. **Token 开销大**：128 段 × ≤512 字符 = 最多 ~6.5 万字符输入，且每段都带完整提示词。
2. **漏词风险**：集合覆盖只保证"稀有词被至少一个片段覆盖"，不保证每个词被 AI 提取到；
   AI 从长文本找词可能漏掉/跳过。
3. **汉字专名靠 AI 发现**：提取层只筛片假名/未登录词；「七星剣」「聖マリア学園」这类
   汉字词依赖 AI 在句子中识别，提取层本身不覆盖。
4. **重复与幻觉**：同一词在多个片段重复出现时，AI 可能给出不同译法（靠投票聚合缓解）；
   也可能幻觉出原文没有的词。

**历史遗留**：文件头标注"本后端已经长时间未维护，目前不推荐使用"。此标注随本次扶正一并移除。

## 二、提取思路（核心：词汇筛选的层次）

把「从文本中找词」从 AI 侧移到本地确定性侧，AI 只做「翻译给定词表」：

```
原文 → 分词（vaporetto，带 POS）
     → ① POS 过滤：只留 名詞（固有名詞/普通名詞/サ変可能…），
        排除 助詞/助動詞/感動詞/接続詞/代名詞/補助記号/記号/接尾辞/非自立/形式/助動詞語幹
     → ② 字符构成过滤：含汉字或片假名（排除纯数字/纯英文/纯标点），长度 ≥2
     → ③ 噪声过滤：拟声词（**组合条件判定**：纯假名 + 重复音节/小字假名/长音特征 + 非词表词；
         不单凭"含长音"判定，避免误伤 スイートルーム 等含 ー 的普通词；ABAB 型叠音
         如 ドキドキ 需匹配双音节重复模式，单字符 `(.)\1` 不够）、H 词表、常见语气词
     → ④ 跨段词频聚合：出现 ≥2 次，或 人名（name 字段/替换表），或 纯片假名词
     → 得到「唯一候选术语表」
     → 分批（如 50 词/批）→ 每批把术语表发给 AI（新提示词：逐词翻译）
     → 按输入词匹配输出行（容错解析）→ 投票聚合（terms 下单词单票，仅去重语义）
     → 最终列表过滤（以 POS 类别 + note 为准，见第七节）→ 存盘
```

**提取规则借鉴**：此前的 consistency-check 词汇筛选经验（POS 白名单
`名詞/動詞/形容詞/形状詞`、排除 `非自立/形式/助動詞語幹`、拟声特征正则
`[ぁぃぅぇぉゃゅょっー]|(.)\1` 等）——按 GenDic 场景收敛为名詞为主的规则。

## 三、目标形态（术语表模式）

| 环节 | segments 模式（现状） | terms 模式（方案） |
|---|---|---|
| 本地提取 | 片假名/未登录词/人名 | 名詞 POS 过滤 + 噪声过滤 + 词频聚合（覆盖汉字专名） |
| AI 输入 | ≤128 段完整片段 | 术语表分批（每批 ≤50 唯一词，附序号） |
| AI 任务 | 从文本中找词并翻译 | 逐词翻译给定词表 |
| 提示词 | GENDIC_PROMPT（提取式） | GENDIC_TERMS_PROMPT（翻译式：逐行 日文\t中文\t备注） |
| 解析 | 容忍自由 TSV | 按输入词匹配输出（AI 跳过/合并/改写 → 缺失词二次补翻） |
| 投票/去重/存盘 | 现有 dic_votes/_build_final_list/_save_generated_dictionary | **投票与落盘复用；最终列表过滤重写**（以 POS 类别 + note 为准，见第七节） |
| 上下文 | 天然有 | 可选 hint：完整原文句 + 词首现起止位置锚定（缓解多义 + 防幻觉） |

**配置**：`gendic.mode: terms|segments`（默认 terms，保留 segments 可回退）；
`gendic.batch_size: 50`；`gendic.context: on|off`（默认 on，附首现完整句）。

## 四、预期收益与风险

### 收益
1. Token 输入降一个量级（词表 vs 完整片段）。
2. 确定性覆盖：所有被筛出的词都会被请求翻译（无集合覆盖缺口）。
3. AI 任务聚焦：少漏词、少幻觉、少重复提取；每个词条一次成稿。
4. 汉字专名由提取层直接覆盖，不再依赖 AI 在文本中识别。

### 风险与缓解
| 风险 | 缓解 |
|---|---|
| 裸术语无语境 → 多义词错译（ロール=角色/卷 等） | `gendic.context: on` 附首现完整句 + 词在句中起止位置锚定；专有名词本身歧义低 |
| 提取层误收常用词/拟声/语气词 → 污染术语表 | 拟声**组合条件**判定（见第二节③）+ H 词表 + 词频门槛 + terms 最终列表过滤（POS 类别 + note，见第七节） |
| 提取层漏收汉字专名（若 POS 规则过严 或 低频单现） | ① 候选来源补充：字典条目/名字表/existing_dict_map 回查原文出现位置；② 汉字专名特殊保留下探 1 次门槛 |
| AI 输出与输入不一一对应（合并/跳过/改写） | 解析按输入词匹配；**缺失词收集后二次补翻（单独成批再请求一轮）**；输出超词表外的行丢弃 |
| 词表过大 → 批次数多 | batch_size 可调；超限截断时**固有名詞/人名永不截断，只截普通名词**（类内按词频降序，见第九节） |
| 现字典重复 | 复用 existing_dict_map 跳过已有词 |
| AI 幻觉出原文没有的词 | grounding 锚定：要求 AI 输出每行带回显原文词并给出在原文的起止位置，无法锚定的行丢弃 |

## 七、决策点 1：terms 模式词类范围（已定）

**结论：terms 模式以「专有名词类」为主，普通名词需满足额外门槛才可入选。**

- 理由：
  1. GenDic 产出的字典会被后续翻译阶段**强制加载**。若把「ロール」这类高频普通名词无脑收入，
     翻译时会强制套用，反而污染翻译质量。
  2. 专有名词（人名/地名/作品名/组织名等）歧义低、跨文本一致性强，是术语表的核心价值。
  3. 现状 `_build_final_list` 的 note 过滤与去重骨架可复用；但 terms 下 `dic_counter>1`
     词频语义失效，**最终列表过滤需按 POS 类别 + note 重写**（见下）。
- 具体规则：
  - **固有名詞（人名/地名/組織名等）**：默认收录，可下探至出现 1 次。
  - **普通名詞（サ変可能/普通）**：
    - 片假名书写：需出现 ≥2 次才收录（外来语术语主体）；与现有字典/名字表匹配可下探 1 次。
    - **汉字书写：默认不单独收录**（防 時間/仕事/ホテル 等高频汉字常用词污染）；仅当
      与现有字典/名字表匹配、或实测确认属作品专名（如特殊物品/招式/地名）时收录。
      这是"召回汉字专名 vs 抑制汉字常用词"的固有权衡，列为实测待验证点，见第五节。
  - **note 标记保留**：人名/地名/拟声等标记必须保留，作为下游过滤与人工辨识依据。
  - **terms 模式最终列表过滤（重写，不复用词频语义）**：terms 下单词单票，`dic_counter`
    恒为 1，现 `_build_final_list` 的 `dic_counter[src] > 1` 分支永不命中，且与"固有名詞
    可下探 1 次"冲突。改为以 **POS 类别 + note 为准**：固有名詞/人名/地名 note 全保留
    （含频次 1）；普通名词 ≥2 才保留（汉字书写按上条）；拟声 note / H 词表 / NULL /
    与已有字典重复 等过滤沿用；`_save_generated_dictionary` 落盘格式复用。
  - 若后续实测发现汉字专名覆盖率不足，可放开到「形 容詞/動詞」白名单（更多但噪声更多），
    由对照实验数据驱动，见第五节。

## 八、决策点 2：模式开关 terms/segments（已定）

**结论：保留双模式长期共存，默认 terms，segments 作为回退与对照保留。**

- 理由：
  1. 实测对照（第五节）依赖 segments 作为基线，不能删。
  2. 某些项目（如专名极多、语境敏感的多义词场景）segments 的"天然上下文"可能更稳，
     保留可回退。
  3. 维护成本低：共享投票/去重/存盘链路，仅提取与提示词分叉。
- 配置：`gendic.mode: terms|segments`，默认 `terms`。
- 不做"默认 segments、观察后切 terms"的过渡态，直接默认 terms 并按第五节对照验证。

## 十、业界实践对照（联网调研结论，供落地参考）

以下策略均来自**经过实践检验**的超长文本术语提取/信息抽取项目，与本方案逐条对应：

### 1. 「统计预筛 + LLM 精排/翻译」两阶段范式（本方案核心，已验证正确）
- 来源：arXiv《Recent Advances in Automatic Term Extraction》(2301.06767) 等多篇综述。
- 结论：用高效统计/规则方法（C-value、词性模式、词频）先生成候选，再让模型只处理候选集，
  可将模型需处理的文本量减少 90% 以上。**本方案即此范式**，方向正确。

### 2. grounding 锚定原文（防幻觉）——本方案新增要点
- 来源：Google LangExtract（38.5k stars，经大量实践）。
- 做法：每个抽取结果带 `char_interval`（在原文的精确位置）；LLM 从示例"幻觉"出的实体
  该区间为空 → 自动丢弃。
- 落地：terms 模式要求 AI 输出每行**带回显原文词 + 在原文起止位置**（或至少词在句中序号），
  无法锚定的行丢弃。也可退化为"词是否确实出现在待翻词表中"校验。

### 3. 完整句上下文优于截断句（多义消歧）
- 来源：LangExtract 的 char_interval + 完整句锚定；多篇 ATE 综述。
- 落地：context 默认 on 时附**完整原文句**而非 ≤30 字截断句——截断句可能切断专名的
  关键修饰成分，完整句 + 位置锚定更可靠。

### 4. 分块并行 + 多轮遍历补召回（可作为可选增强）
- 来源：LangExtract `max_char_buffer=1000` 分块、`extraction_passes=3` 多轮。
- 说明：本方案词表分批天然并行（复用现有 workers/Semaphore），无需多轮遍历；
  若实测补翻后仍有低频漏词，可考虑对"只出现 1 次且未翻译"的词做一轮独立复查。

### 5. 纯统计方法（YAKE!/Rake/C-value）可作补充预筛
- 来源：TermExtract、YAKE! 等工具。
- 说明：可选增强——对超长文在分词后补充"左右邻接熵/文档频率(DF)"过滤，比纯词频更能
  去伪专名，且零 AI 成本。非必须，建议二期再加。
