## 分析报告

### 一、现状全景（已查档核实）

**继承树**（全部 8 个类都直接/间接继承 `BaseTranslate`）：

```
BaseTranslate（基类，约 1460 行，方法 40+）
├── ForGalJsonMulitChat（约 2100 行，核心翻译引擎）
│   ├── ForBRStation（换行修复，重写 batch_translate）
│   └── ForImproveTranslation（改进轮，重写 batch_translate）
├── ForFileMetaData（文件元数据，重写 batch_translate，签名不同）
├── ForBatchMetaData（批次元数据，重写 batch_translate，签名不同）
├── ForGlobalPrompt（全局提示词，重写 batch_translate，签名不同）
├── ForPlotRouteMap（剧情路线图，重写 batch_translate，签名不同）
└── GenDic（字典生成，重写 batch_translate，签名不同）
```

### 二、核心问题（基于证据）

**问题 1：`batch_translate` 不是多态接口，而是 7 种互不兼容的同名方法**
各子类签名完全不兼容，且**均不调用 `super().batch_translate()`**：
| 类 | batch_translate 签名 | 返回 |
|---|---|---|
| BaseTranslate(1313) | `(filename, cache_file_path, trans_list, num_pre_request, ...)` | `CTransList` |
| ForGalJsonMulitChat(2056) | `(filename, ..., translist_hit, translist_unhit)` 走 `_batch_translate_common` | `CTransList` |
| ForFileMetaData | `(json_list, filename="")` | `None` |
| ForBatchMetaData | `(json_list, filename="")` | `None` |
| GenDic | `(json_list)` | `bool` |
| ForGlobalPrompt | `(compressed_data, external_info)` | `bool` |
| ForPlotRouteMap | `(structure_type, user_outline)` | `bool` |

基类的 `batch_translate` 只被 `ForGalJsonMulitChat` 体系"间接"用到（通过 `_batch_translate_common`），其余 5 类完全不用。**基类的 `translate`(1310) 是空 `pass` stub**，真正实现只在 `ForGalJsonMulitChat.translate`(1843)。

**问题 2：`BaseTranslate` 是"上帝基类"，承载两类截然不同的职责**
- **翻译轮**（仅 ForGalJsonMulitChat 体系用）：`_batch_translate_common`、`translate`、`_build_idx_tip`、`_apply_history_result`、`_normalize_parsed_translation_text`、`_append_parsed_translation_result`、`restore_context`、`_set_temp_type`、`dynamic_num_per_request*` 等约 15 个方法。
- **通用 API/工具层**（全部 8 类共用）：`__init__`、`ask_chatbot`、`init_chatbot`、`clean_up`、`shutdown`、`_check_stop_requested`、`_interruptible_sleep`、`_coerce_bool` 等。

但 5 个非翻译类（ForFileMetaData/ForBatchMetaData/ForGlobalPrompt/ForPlotRouteMap/GenDic）被迫继承整套翻译轮方法，尽管它们**只依赖 API 层 + 各自独有逻辑**。已逐类核实：它们只用 `ask_chatbot`/`init_chatbot`/`_build_prompt_request`/`_apply_internal_prompt_template_overrides` 等 API 层方法，`_batch_translate_common`/`restore_context` 等翻译方法完全没用。

**问题 3：`__init__` 模板重复 8 次**
每个子类都重复同样 4 行：`self.system_prompt=...`、`self.trans_prompt=...`、`self._apply_internal_prompt_template_overrides()`、`self.init_chatbot(...)`（已核对 ForGalJsonMulitChat:1348-1351、ForFileMetaData:47-52、ForBatchMetaData:64-65、ForPlotRouteMap:94-95、ForGlobalPrompt:184-185、GenDic:71-72、ForBRStation:57、ForImproveTranslation:48）。

**问题 4：模块级数据/工具函数散落在 `ForGalJsonMulitChat.py` 顶部（非本类职责）**
`parse_interval`、`strip_chunk_suffix`、`normalize_batch_intervals`、`detect_line_break_symbol`、`FileMetaData`、`load_file_metadata`、`load_file_metadata_map`、`BatchMetadata`、`load_batch_metadata_map` 等约 600 行数据实体与工具函数，被 `LLMTranslate.py`、`ForBatchMetaData.py`、`ForPlotRouteMap.py`、`tests/` 大量 import（已核实 20+ 处），却定义在翻译类文件里——**低内聚、高耦合**。

**问题 5：全局提示词/路线图装配逻辑重复 4 份**
`_ensure_global_prompt_loaded` 在 `ForGalJsonMulitChat`(1407)、`ForFileMetaData`(68)、`ForBatchMetaData`(120)、`ForPlotRouteMap`(100) 各写一份；`_format_global_prompt_as_context` 从 `ForGlobalPrompt` 四处重复 import 包装；`_format_route_context_for_file` 在 ForGalJsonMulitChat(1473) 与 ForBatchMetaData(161) 重复。

**问题 6：`init_gptapi` 手写 8 分支 match 分发**（LLMTranslate:2449-2475），虽可接受，但新增后端需改此函数 + 忘记 import 即 ValueError，可改为注册表/装饰器。

### 四、完整分步迭代方案（6 次提交，符合 3~8 次）

#### 提交 1：拆分 `BaseEngine`，翻译轮与 API 层解耦（低风险，纯移动）
- **动作**：新建 `BaseEngine.py`，把 `BaseTranslate` 中 8 类共用的 API 层方法原样移入：`__init__`（config/eng_type/proxy/token/语言/RPM 解析）、`ask_chatbot`、`init_chatbot`、`clean_up`、`shutdown`、`_build_thinking_params`、`_interruptible_sleep`、`_wait_for_global_rpm_slot`、`_record_request_health`、`_check_stop_requested`、`_is_stop_requested`、`_coerce_bool`、`_coerce_positive_int`、`_apply_internal_prompt_template_overrides`。`BaseTranslate(BaseEngine)`。
- **风险**：纯移动不改逻辑，跑全量 unittest + `python run_vitest.py` 即可验证。
- **关键点**：`__init__` 中 `load_guideline_file`、OpenCC、`request_health_metrics` 属 API 层范畴，一并移入；翻译轮字段（`dynamic_num_per_request*`、`restore_context_mode` 等）留在 BaseTranslate。

#### 提交 2：非翻译类改继承 `BaseEngine`（低风险，改 5 处继承）

- **验证**：全量 unittest（尤其 test_forglobalprompt_glossary_scene、test_forbatchmeta、test_dict_pipe_separator、GenDic 相关）。

### 五、潜在 bug 与规避（已预判）
1. **提交 2 方法解析漂移**：若某非翻译类偷偷用了翻译层方法（已 grep 证实没有，但提交后需再 grep `self\._batch_translate_common|restore_context` 在该 5 类中为 0）。
2. **提交 3 import 断裂**：`ForBatchMetaData`/`ForPlotRouteMap`/`LLMTranslate`/`tests` 共 20+ 处 import。规避：`ForGalJsonMulitChat.py` 保留 re-export，新模块用唯一来源，最后再删 re-export。
3. **提交 5 行为不等价**：4 份 `_ensure_global_prompt_loaded` 的 `inject_guideline` 判定、异常回退逻辑可能微差。规避：合并前逐份 diff，先加等价性断言测试（如 global_prompt 块输出快照对比），再替换。
4. **多 worker 上下文**：`BaseEngine.__init__` 不动 `WORKER_ID_CTX`/`set_live_snippets` 相关调用路径（在 translate 层），避免破坏上次的译文预览多 worker 改造。
5. **注册表替换 init_gptapi**：`LLMTranslate` 里 8 个分支含"延迟 import + 注释"，改为注册表后需保留延迟 import 语义（避免 import 时拉入全部后端依赖），用 `importlib` 惰性加载。
